# 阿里云、火山引擎、微软、谷歌模型接入修改方案

本方案只覆盖截图中的四家厂商：阿里云百炼、火山引擎、微软 Azure、谷歌。翻译 LLM 和总结 LLM 能走 OpenAI 兼容接口的，不新写插件。专有语音协议才改现有插件或新建插件。

## 1. 目标

管理后台里的一条模型配置，能够驱动一次语音会话实际调用对应厂商。配置项包括地址、密钥、模型名、音色和厂商专有参数。Agent 按 `protocol` 选择插件，不再把厂商地址写死在代码里。

会话仍由 HiMarket 签发。`AgentJobMetadata` 里带上解析后的 `llm`、`stt`、`tts`，以及实时通话时的 `realtime`。插件只负责把这块绑定转换成厂商请求。

## 2. 改动范围

| 对象 | 动作 | 原因 |
| :--- | :--- | :--- |
| `livekit-plugins-openai` | 不改代码 | Azure OpenAI、百炼文本、方舟文本都是 Chat Completions 或 Realtime 的同类接口，改 `base_url`、密钥和模型名即可 |
| `livekit-plugins-azure` | 不改代码 | MAI-Voice-2.1 是 Azure Speech 的音色名，现有 TTS 的 `voice` 参数可以传入 |
| `livekit-plugins-google` | 修改 | Chirp 3 是 Speech-to-Text V2；Gemini 3.8 Flash TTS 走 Gemini 音频输出，不是 Cloud TTS |
| `livekit-plugins-dashscope` | 新建 | 阿里流式 ASR、Qwen TTS、Qwen Omni Realtime 没有官方插件 |
| `livekit-plugins-volcengine` | 新建 | 豆包流式识别、Seed-TTS、Seeduplex 没有官方插件 |
| `himarket-rs` 模型目录和 Agent | 修改 | 增加协议名和专有参数，并按协议实例化插件 |

不改 LiveKit Server。厂商密钥留在 HiMarket，通过任务元数据交给 Agent，不放进 Android 客户端。

## 3. 只改控制台配置的模型

这些行使用已有插件，协议沿用 `openai_chat`、`openai_stt`、`openai_tts`、`openai_realtime`。

| 用途 | 厂商 | 模型 | base_url | 插件 |
| :--- | :--- | :--- | :--- | :--- |
| 翻译、总结 LLM | 阿里云 | `qwen3.8-max` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `openai.LLM` |
| 翻译、总结 LLM | 火山引擎 | `doubao-seed-2-1-pro-260915` | `https://ark.cn-beijing.volces.com/api/v3` | `openai.LLM` |
| 翻译、总结 LLM | Azure | 部署名 `gpt-5.6-sol` | `https://{resource}.openai.azure.com/openai/v1` | `openai.LLM`，`api_secret` 存 Azure API version |
| 翻译 LLM | 谷歌 | `gemini-3.8-flash` | Gemini OpenAI 兼容地址 | `openai.LLM` |
| 总结 LLM | 谷歌 | `gemini-4-argon` | 同上 | `openai.LLM` |
| ASR | Azure | `gpt-4o-transcribe` | Azure OpenAI 音频地址 | `openai.STT` |
| TTS | Azure | MAI-Voice-2.1 | Azure Speech 区域地址 | `azure.TTS`，`voice` 为 MAI 音色名 |
| Realtime | Azure | `gpt-realtime-2.1` | Azure Voice Live 或 OpenAI Realtime | `openai.realtime.RealtimeModel` |

Agent 里这几类协议已经按 OpenAI 兼容 HTTP 调用。本阶段只把目录条目补进 `catalog/livekit_models.json`，密钥在控制台写入。

## 4. 修改 `livekit-plugins-google`

插件继续导出 `STT`、`TTS`、`LLM`、`RealtimeModel`。只改识别和合成两条路径。

### 4.1 Chirp 3 识别

新增构造参数 `model="chirp_3"`，默认仍保持插件原来的模型，避免旧配置行为变化。

请求改为 Cloud Speech-to-Text V2：

- 地址：`https://{location}-speech.googleapis.com/v2/projects/{project}/locations/{location}/recognizers/_:recognize`
- 识别器配置里的 `model` 为 `chirp_3`
- 音频为 16 kHz、单声道、LINEAR16
- `language_codes` 默认 `cmn-Hans-CN`，可由配置覆盖

`api_key` 继续放 API Key。`api_secret` 存 `project_id`。`voice` 字段复用为 `location`，空则用 `global`。

`recognize()` 返回一个 `SpeechEvent`，文本放在第一条 alternative。流式识别用 V2 `streamingRecognize`，实现 `stream()`。

### 4.2 Gemini 3.8 Flash TTS

新增 `model="gemini-3.8-flash-tts"`。当模型名以 `gemini-` 开头且以 `-tts` 结尾时，不走 Cloud Text-to-Speech，改走 Gemini `generateContent`：

- 地址：`https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
- 请求声明音频输出模态
- 响应里的 PCM 或 WAV 转成 `tts.SynthesizedAudio`
- `sample_rate` 固定 24000，单声道

旧的 Cloud TTS 音色路径保持原样。只有命中 Gemini TTS 模型名才走新分支。

### 4.3 Gemini Live

`gemini-3.8-live` 仍用插件里的 Gemini Live Realtime。若模型枚举写死，就把枚举放宽为字符串，让控制台传入的模型名直接发给 Live API。不新写一套 WebSocket。

## 5. 新建 `livekit-plugins-dashscope`

包名 `livekit-plugins-dashscope`，导入名 `livekit.plugins.dashscope`。依赖 `livekit-agents` 和 `aiohttp`。实现三个类。

### 5.1 `STT`

对应 `qwen-audio-3.1-asr-flash-streaming`。

```python
STT(
    model="qwen-audio-3.1-asr-flash-streaming",
    api_key="sk-...",
    base_url="wss://dashscope.aliyuncs.com/api-ws/v1/inference",
    language="zh",
)
```

- `recognize()` 把整段 16 kHz PCM 打成百炼流式识别任务，收完最后一句再返回
- `stream()` 按百炼要求分片发送 PCM，每片回传 partial 和 final
- 鉴权头使用 `Authorization: Bearer {api_key}`
- 任务模型名来自 `model`

### 5.2 `TTS`

对应 `qwen-audio-3.1-tts-flash`。

```python
TTS(
    model="qwen-audio-3.1-tts-flash",
    voice="Cherry",
    api_key="sk-...",
    base_url="https://dashscope.aliyuncs.com/api/v1",
)
```

`synthesize()` 请求百炼语音合成，把返回的 PCM 或 WAV 规范成 24 kHz、单声道。`voice` 为空时使用百炼默认音色。

### 5.3 `RealtimeModel`

对应 `qwen3.8-omni-flash-realtime`。按百炼实时多模态协议连接 WebSocket，会话参数里带上模型名。音频输入输出为 PCM。这个类实现 LiveKit 的 realtime 接口：`session()` 负责收发音频帧和文本事件。WebRTC 传输只在百炼明确要求 SDP 交换时再加，第一版用 WebSocket 音频帧，和第二版截图里的 WebRTC 说明对齐。

## 6. 新建 `livekit-plugins-volcengine`

包名 `livekit-plugins-volcengine`。鉴权使用控制台里的两段密钥：`api_key` 为 Access Token，`api_secret` 为 App ID。`model` 放 Resource ID。

### 6.1 `STT`

对应豆包流式语音识别 2.0，Resource ID `volc.seedasr.sauc.duration`。

- 连接火山 SAUC 二进制 WebSocket
- 首包写入 App ID、Access Token、Resource ID、音频格式和语言
- 后续包发送 16 kHz PCM
- `recognize()` 等待最终句，`stream()` 转发中间结果

### 6.2 `TTS`

对应 `seed-tts-2.0`。

- HTTP 或 WebSocket 调用火山 OpenSpeech 合成
- `voice` 传音色，例如控制台里配置的豆包音色 ID
- 输出统一为 24 kHz PCM

### 6.3 `RealtimeModel`

对应豆包实时语音 3.0 Seeduplex。

- 连接火山实时通话 WebSocket
- 事件帧使用火山定义的 JSON，不套 OpenAI Realtime 事件名
- Resource ID 由开通后的值填进 `model`，插件不写死
- 音频帧和文本事件映射到 LiveKit realtime 会话

## 7. HiMarket 配置和 Agent 分发

`ai_model_config` 增加可空列 `extra_json`。专有参数放这里，避免继续占用 `voice` 的含义。

| 字段 | 用途 |
| :--- | :--- |
| `kind` | `llm`、`stt`、`tts`、`realtime` |
| `protocol` | 见下表 |
| `base_url` | 厂商地址 |
| `api_key` | Bearer、DashScope Key 或火山 Access Token |
| `api_secret` | Azure API version、GCP project、火山 App ID |
| `model` | 模型名、部署名或 Resource ID |
| `voice` | 音色 |
| `extra_json` | `location`、`language`、`resource_id` 等 |

新增协议名：

| protocol | 插件类 |
| :--- | :--- |
| `google_stt` | `google.STT` |
| `google_tts` | `google.TTS` |
| `google_realtime` | `google` realtime |
| `azure_tts` | `azure.TTS` |
| `dashscope_stt` | `dashscope.STT` |
| `dashscope_tts` | `dashscope.TTS` |
| `dashscope_realtime` | `dashscope.RealtimeModel` |
| `volcengine_stt` | `volcengine.STT` |
| `volcengine_tts` | `volcengine.TTS` |
| `volcengine_realtime` | `volcengine.RealtimeModel` |

`voice-agent/agent_main.py` 增加一个工厂。`transcribe()`、`synthesize()` 和 realtime 入口只看 `binding["protocol"]`，把 `base_url`、`api_key`、`api_secret`、`model`、`voice` 传进对应构造函数。未知协议直接报错，不再回退到本地 Whisper 或 Piper。

目录文件 `catalog/livekit_models.json` 补上截图中的 16 条。密钥留空，状态为未启用。管理员保存密钥后再设为默认。

## 8. 实施顺序

1. 控制台补齐四家的目录条目和 `extra_json`，先让 LLM 兼容接口能被选中。
2. 修改 `livekit-plugins-google` 的 Chirp 3 和 Gemini TTS，并用固定短音频、短文本做契约测试。
3. 实现百炼 STT、TTS，再实现 Omni Realtime。
4. 实现火山 STT、TTS，再实现 Seeduplex。
5. Agent 安装这两个新包，并按协议分发。用管理后台切换默认模型，确认新会话使用新厂商，旧会话不受影响。

## 9. 验收

- 只改控制台配置，翻译和总结能分别打到 `qwen3.8-max`、`doubao-seed-2-1-pro-260915`、`gpt-5.6-sol`、`gemini-3.8-flash`、`gemini-4-argon`。
- 同一段 16 kHz 中文音频，Chirp 3、Azure `gpt-4o-transcribe`、百炼 ASR、火山 SAUC 都能返回文本。
- 同一句中文，Gemini TTS、MAI-Voice-2.1、Qwen TTS、Seed-TTS 都能返回 24 kHz PCM。
- Gemini Live、GPT-Realtime 2.1、百炼 Omni、火山 Seeduplex 能建立双向音频会话并返回第一段音频。
- 密钥只出现在 HiMarket 和服务端任务元数据里，控制台列表仍然只显示末四位。
